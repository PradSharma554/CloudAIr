# x402 paywall — v1 stub and the real integration

## What ships in v1

`internal/x402/x402.go` is a middleware seam. When a site's
`settings.monetization.enabled` is true and a request has no `X-PAYMENT`
header, agent-facing endpoints return **HTTP 402** with an x402-spec body:

```json
{
  "x402Version": 1,
  "error": "payment required to access this resource",
  "accepts": [{
    "scheme": "exact",
    "network": "base-sepolia",
    "maxAmountRequired": "50000",
    "resource": "/sites/example-com/llms.txt",
    "description": "Access to example.com agent content via CloudAIr",
    "payTo": "0x…",
    "asset": "USDC",
    "mimeType": "text/markdown"
  }]
}
```

Any `X-PAYMENT` header currently passes (stub). The dashboard shows the
monetization toggle as "coming soon".

## The real integration (later phase)

1. **Verify**: POST the `X-PAYMENT` payload + payment requirements to a
   facilitator's `/verify` (Coinbase's hosted facilitator has a free tier for
   Base). Reject with 402 on failure.
2. **Settle**: after serving the response, POST to `/settle`; record the tx
   in a new `payments` table (site_id, agent info, amount, tx hash).
3. **Dashboard**: earnings panel per site; payout address in settings
   (`settings.monetization.pay_to`, already modeled).
4. **Discovery**: advertise pricing in llms.txt and the MCP server
   instructions so agents can decide before paying.

The only contract v1 commits to is the middleware seam — verification slots
into `x402.Middleware` without touching handlers.
